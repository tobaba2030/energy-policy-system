# 国家电网/南方电网 科技项目技术研究报告评审技能 v3.0

本技能用于对国家电网/南方电网科技项目**技术研究报告**进行结构化评审。本技能不生成报告，仅对已撰写完成的报告输出评审意见。

> ⚠️ 适用范围：科技项目**技术研究报告**（基础研究、应用基础研究、应用研究层次）。
> ⚠️ 不适用范围：工程实施类、产品开发类、平台部署类文档。这类报告应使用其他评审标准（如工程评审、设计评审）。

---

## 评审目标

四个核心评审维度：

1. **前瞻性** — 选题方向、目标设定与技术路线是否瞄准未来 3-10 年的真问题，是否回应"双碳"目标与新型电力系统建设需求。
2. **理论创新性** — 方法论、数学模型、算法机理层面的原创贡献是否清晰、是否与已有工作有实质性区分，是否避免"工程实现包装成理论创新"。
3. **整体逻辑结构** — 背景→问题→综述→方法→预期成果→意义链路是否闭合；关键难点、研究内容、预期成果是否互相呼应。
4. **表述精炼度与电网科技报告风格** — 是否以自然段行文、是否避免 AI 味"加粗冒号列表"、是否使用电网领域规范术语、参考文献是否符合 GB/T 7714-2015。

各维度详细评分锚点、必查项、推荐查项与改写示范，见 `checklist/` 目录下四个文件。

## 评审主流程（5 步）

### Step 1 — 报告解析

- 输入若为 `.docx` 或 `.pdf`，先用 `pandoc <file> -o <name>.md` 转 Markdown（如系统未安装 pandoc，则提示用户提供 Markdown 版本，或回退到逐段读取核心章节）。
- 用 `Read` 工具加载 Markdown 全文，确认章节结构能被正常识别。

### Step 2 — 客观指标检查

并行运行三个脚本（脚本统一输出 JSON 到 stdout）：

```bash
python3 ~/.claude/skills/state-grid-keyan/scripts/extract_structure.py <report.md>
python3 ~/.claude/skills/state-grid-keyan/scripts/style_check.py <report.md>
python3 ~/.claude/skills/state-grid-keyan/scripts/ref_check.py <report.md> --current-year 2026
```

输出含义：

- `extract_structure.py`：章节大纲、各级标题数量、各章字符数与段落数、平均段落字数、最长段落、过短章节与超长段落警告。
- `style_check.py`：AI 味"加粗冒号"段比例与连续运行、过短/过长段落、口语化与夸大表述命中、术语规范警告。
- `ref_check.py`：参考文献总量、类型分布（J/M/C/D/S）、中英文比例、近 5 年占比、核心 venue 覆盖、格式问题清单与汇总标志。

将三段 JSON 输出作为客观证据，写入评审意见的附录章节。

### Step 3 — 四维度评审

依次加载并参照下列 checklist 文件（用 `Read` 工具读取），按其评分锚点对报告打分（每维 0-10 分）并撰写评语：

- `checklist/forward_looking.md` — 前瞻性
- `checklist/theoretical_innovation.md` — 理论创新性
- `checklist/logical_structure.md` — 整体逻辑结构
- `checklist/style_conciseness.md` — 表述精炼度与电网科技报告风格

每维度评审要求：

1. **先打分**：参照评分锚点选择档位，再在档位区间内微调；分数必须有具体证据支撑，不可拍脑袋。
2. **再写评语**：以自然段行文，先给出总体判断，再列举 2-4 条具体问题点（引用报告原文位置——"第 X 章 / 第 X.Y 节 / 第 N 段"），最后给出针对性建议。
3. **必查项必须逐条标记 pass/fail**：在内部判断中标注，外化到评审意见时融入评语。
4. **客观指标结合主观判断**：脚本输出（AI 味段比例、参考文献新近度等）应作为评语的支撑证据，但不能替代主观判断。

### Step 4 — 形成评审意见 Markdown

加载 `templates/review_report_template.md`，按其结构填写：

- 总体评价（200-400 字自然段）
- 维度评分表
- 分维度评审意见（4 节）
- 章节级问题清单（表格，逐条问题→位置→类型→建议）
- 修改建议与下一步（必须修改 / 建议修改 / 可选优化 三档）
- 参考文献评审摘要
- 附录：脚本输出摘要（不需贴完整 JSON，提取关键指标即可）

写入工作目录 `{原报告名}_评审意见.md`。

### Step 5 — 调用 docx-cn 转 Word

调用 `docx-cn` skill：

- 模板：`report`（含封面、目录）
- 封面字段：评审对象 / 申请单位 / 评审人 / 评审日期 / 报告版本号（从 Markdown frontmatter 提取）
- 输出：`{原报告名}_评审意见.docx`，保存到与原报告相同的目录。

完成后提示用户：

1. 打开 Word 后按 Ctrl+A → F9 刷新目录。
2. 补充封面中评审人签名等占位信息。
3. 如需正式归档，请在评审意见前增加评审委员会信息页。

## 评审纪律与写作规范

### 评审纪律

- **客观性优先**：每条评语必须有"报告原文位置 + 问题描述"两要素，不接受"印象式批评"。
- **针对研究而非作者**：所有问题指向报告内容与论证结构，不评价作者个人能力。
- **建设性建议**：每条问题应配对应改进方向，避免"只破不立"。
- **避免无依据的赞美**：高分必须列出具体证据，不允许"该报告水平很高、创新性很强、逻辑清晰"等空洞表述。
- **避免无依据的贬低**：低分必须给出具体可改进的方向，不允许仅说"质量不行"。
- **科技报告 ≠ 工程文档**：如发现报告大量篇幅讨论工程实施、平台部署、流程改造、组织架构等内容，应在"逻辑结构"维度扣分，并在意见中明确指出"超出科技项目研究报告范畴"。

### 评审意见的语言风格

评审意见本身也应遵循电网科技报告的写作风格：

- 以自然段行文，每段 150-300 字，有中心句。
- 禁止评审意见中出现"加粗前缀+冒号+一句话"的 AI 味结构（评分表、问题清单等必要表格除外）。
- 使用"本次评审认为""报告中第 X 节存在 Y 问题"等正式表述，避免"我觉得/我们看到/接下来"等口语。
- 引用报告原文时使用书名号《》或引号""标注关键短语。
- 避免感叹号、夸大修辞、emoji 与装饰性 Markdown 符号。

### 参考文献评审的尺度

- 参考文献总量 ≥60 条为合格门槛，<60 条直接在"前瞻性"或"逻辑结构"维度扣分并提出补充建议。
- 英文文献占比 <30% 视为对国际前沿关注不足，扣分。
- 近 5 年文献占比 <50% 视为综述时效性不足，扣分。
- 关注核心 venue 覆盖（IEEE Trans on Power Systems/Smart Grid/Power Delivery、中国电机工程学报、电力系统自动化、电网技术等）：若核心 venue 覆盖 <3 个，应在评语中提示。
- 不要求 Claude 联网核实文献真实性；但若发现明显格式错误（缺年份、缺卷期、缺页码），应在评审意见中列出。

## 关键注意事项

1. **本技能仅评审，不生成报告。** 用户若需生成报告，应另用其他生成型 skill 或自行撰写。
2. **不评价工程实施、产品开发、平台部署。** 报告中此类内容应在评审意见中明确指出"超出科技项目研究报告范畴"。
3. **客观脚本是支撑而非替代主观判断。** 即便脚本指标全绿，仍需主观评估前瞻性与理论创新；反之即便指标飘红，也需结合内容判断是否构成实质问题。
4. **评分锚点是参照而非硬规则。** Claude 应基于报告整体水平在锚点附近灵活打分，并清楚说明依据。
5. **评审意见本身要符合电网科技报告写作规范。** 写评审就是写专业文档，禁止用 AI 味的"加粗冒号列表"作为评审意见主体结构。
