# 理论创新性评审 Checklist

> 评估科技项目技术研究报告在方法论、数学模型、算法机理层面的原创贡献。重点排查"工程实现包装成理论创新"的现象。

---

## 评分锚点（0-10 分）

| 分数 | 描述 |
|------|------|
| 9-10 | 至少一个核心创新点具备可发表 CCF-A / IEEE Trans 级别的理论贡献；建模角度、数学表达、约束形式或求解机理上与已有工作存在本质差异；理论假设清晰、边界条件明确；给出严格的可行性论证或初步收敛性/复杂度分析。 |
| 7-8  | 创新点在方法层面具有明确改进（如新损失函数、新结构、新表征、新约束），但与已有工作相比仍属增量贡献；理论刻画基本完整。 |
| 5-6  | 创新点为多种成熟方法的有机组合或场景适配；缺少独立的理论分析；与已有文献缺乏点对点对比。 |
| 3-4  | 创新点停留在"应用现有方法解决电网新场景"层面；本质上是工程实现而非理论研究。 |
| 0-2  | 报告未给出可识别的创新点，或所谓创新点为常识级方案（如简单堆叠两层神经网络、做参数调优、写代码工程化）。 |

---

## 必查项（pass / fail）

- [ ] 报告是否在第二章/第三章明确列出 3-5 条可识别的"创新点"，并对每条单独展开？
- [ ] 每条创新点是否说明：① 解决了哪个具体科学/技术问题；② 与现有方法的差异；③ 为什么是"理论"层面的进步而非工程实现？
- [ ] 是否对核心方法给出数学表达（公式、损失函数、约束、优化目标）？
- [ ] 是否在创新点描述中引用至少 1-2 篇近年代表性对照工作，并阐述差异？
- [ ] 是否避免将"建设平台/开发系统/调优参数/扩充数据集/适配业务流程"伪装成理论创新？

---

## 推荐查项（影响细分得分）

- 是否说明所提模型/方法的可学习参数、表示空间、归纳偏置（inductive bias）相对于已有工作的差异。
- 是否给出理论性质讨论：可识别性、稳定性、收敛性、泛化界、复杂度上界等（哪怕只有一项）。
- 创新点之间是否相互独立又彼此支撑，构成完整的方法体系？还是相互重复表述？
- 是否避免使用"首创、首次、国内领先、国际领先"等无据点的自我评价？需有具体对比依据。
- 是否使用物理一致性、约束嵌入、可解释性等机理性维度论证创新合理性，而非仅靠"准确率更高"。
- 是否给出该方法在最简代表性算例上的初步验证或数学推导，证明其确实可行？

---

## 常见问题模式与示例

**问题 1：把"应用 + 调参"叫做创新**
- 反例："本项目首次将 Transformer 应用于电力负荷预测，提出基于注意力机制的新方法。"
- 改进："本项目针对电力负荷时序中存在的多尺度周期与外生事件耦合问题，提出一种带先验掩码的稀疏注意力结构，证明其在 X 假设下的样本复杂度优于标准 self-attention。"

**问题 2：创新点为口号式表述**
- 反例：创新点 = "提出新型电网智慧识别框架"。
- 改进：必须降维到具体技术对象，如"在 X 物理量、Y 边界条件下，提出基于 Z 的新型表征 r(x)，并给出其相对于已有表征 r'(x) 的可分性提升上界"。

**问题 3：堆砌深度学习模型作为创新**
- 反例：将 CNN+LSTM+Attention 串联，称为"多模态深度融合创新"。
- 改进：要求作者明确说明这种组合解决的具体理论难题（如长程依赖建模、多模态对齐、分布外泛化等），并对每一模块的必要性给出消融分析计划。

**问题 4：缺少与已有工作的点对点对比**
- 反例：综述部分罗列了 20 篇近期工作，但创新点描述中未引用其中任意一篇做对照。
- 改进：每条创新点末尾应增加"与文献 [x][y] 相比，本项目的差异在于……"的对照陈述。

**问题 5：数学表达缺位**
- 反例：通篇仅以中文描述方法步骤，未给出任何数学符号或公式。
- 改进：核心方法至少给出：① 问题形式化表达；② 目标函数；③ 关键约束；④ 求解算法骨架。

**问题 6：把"工程实现"叫做"突破"**
- 反例："开发了一套支持多源数据接入的电网监测系统，是本项目重要创新点。"
- 改进：说明该系统背后承载的理论问题（如异构图数据的对齐建模），并将"系统"重新定位为"方法的验证载体"。
