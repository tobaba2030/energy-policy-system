# AI+科技项目策划简表生成

针对电网领域科技项目申报，依据用户提供的业务问题，参照国家重点方向与规范格式，生成高质量的科技项目申报材料，涵盖项目标题、业务问题、预期成效、研究内容、考核指标五部分，并可进行格式审核。

## 一、技能模块体系

### 模块1：业务问题梳理
**目标**：梳理用户提供的原始业务需求，识别核心痛点，明确关键现状量化指标。

**输入要求**：
- 用户输入的业务问题描述
- 包含关键现状量化指标
- 明确问题对业务的负面影响

**输出要求**：
- 凝练的业务问题描述（300字以内）
- 所有数据指标标注清晰的数据来源
- 字数控制在250-280字范围内

### 模块2：项目标题生成
**目标**：生成符合规范的科技项目标题，紧扣国家重点方向与垂直场景。

**撰写要求**：
- **核心特征**：赛道精准，紧扣新型电力系统、新能源并网等国家重点方向，锁定垂直细分场景（如农村配网、山地风电等），直击行业真实痛点（如新能源消纳、电压暂降等），融入多模态感知、云边协同、电力大模型等前沿技术，兼顾理论研究与工程落地。
- **强制格式**：严格套用句式——《【限定约束条件/应用场景】+【研究对象/核心痛点】+【核心技术路径/技术方法】+【关键技术研究/装备研制/示范应用】》
- **禁止事项**：禁止题目空泛无场景/痛点，禁止纯理论无落地，禁止脱离新型电力系统战略方向，禁止句式口语化。严禁使用任何具体的地名（如曲靖、昭通）、具体公司名，必须提炼为具有行业代表性的通用场景。
- **字数限制**：标题不超过39个字

**参照示例**：
- 《面向主配网协同分析的科学计算模型构建技术及应用》
- 《支撑规模化超快充电设施接入与调控的智能量测技术研究及示范》
- 《计及电动汽车迁徙规律的农村配电网尖峰负荷平抑保供关键技术》

### 模块3：预期成效撰写
**目标**：针对业务问题，描述项目完成后的预期成效，量化指标与业务问题现状指标一一对应。

**撰写要求**：
- **篇幅控制**：240-280字，精炼聚焦
- **内容结构**：采用连贯段落或3-4个分点，每点针对一个核心业务指标的提升
- **语言风格**：自然流畅、符合业务逻辑，避免机械堆砌
- **量化推导**：提升幅度需有合理依据（如参考行业目标、区域规划或典型项目经验）
- **禁止内容**：不得出现技术指标（如算法准确率、系统延迟等）、知识产权数量、论文发表、人才培养等非业务类成效

**不建议写法**：
"预期将覆盖率从当前60%提升至95%以上，较当前提升35个百分点，参考全国灵活调节资源统筹调度'十四五'规划目标，基本实现全量纳管。"

**建议写法**：
"预期实现符合调节要求的高耗电工业园区自备电厂全量纳管，调度覆盖率提升至95%以上，基本消除纳管盲区，有效支撑新能源消纳。"

### 模块4：研究内容撰写
**目标**：撰写符合规范的研究内容，逻辑连贯，覆盖所有核心技术路径。

**撰写逻辑**：
问题导向→总体目标→分点研究→成果落地，总字数约500字，使用正式学术表述。

**具体要求**：
1. **开篇总起**：用1句话（30-50字）点出核心痛点和研究目标，格式为"针对……（问题1、问题2）等问题，开展……（研究主题）研究，具体包括："。不需要体现具体的数据指标。
2. **分点展开**：3-5点，每点80-100字，遵循"研究+具体场景/对象+核心技术路径+预期效果"句式，逐步递进，每点须提及具体技术方法。所有描述中严禁出现具体地名或企业名，场景仅使用通用术语。
3. **结尾落地**：一般来说，最后一点都是研制XX系统（功能模块），并选取XX地点开展示范应用，体现工程落地性。

**字数限制**：研究内容不能超过500字，在统计空格与换行的情况下，字数不能超过500字，但是也不能少于450字。

### 模块5：考核指标撰写
**目标**：撰写量化可验证的考核指标，覆盖全部核心成果。

**撰写逻辑**：
成果量化→指标具体→可验证→贴合研究内容，覆盖全部核心成果。

**具体要求**：
1. **分点要求**：共4-5点，每点对应研究内容中的一项核心成果。必须以"形成/建立/研发/搭建/研制+具体成果形式"开篇，明确考核的核心成果。
2. **量化可验证**：每点必须包含具体量化数值（如"准确率≥95%""响应时间≤24小时""效率提升10%以上"等），拒绝"提升、优化"等模糊表述，确保指标可考核、可验收。
3. **应用适配**：需体现成果的应用场景或适配范围，部分指标须明确试点应用要求（如示范应用、区域推广）。
4. **拔高收尾**：最后一点须明确整体技术水平（如区域领先、行业对标）或成果的标准化与可复制推广价值。
5. **关联与覆盖**：所有指标须与研究内容强关联，覆盖全部核心成果，不出现无关指标，不遗漏关键考核点。

### 模块6：格式审核
**目标**：对标南方电网科技项目指南/需求评审标准，进行合规性审查与专业深度评审。

**硬性形式审查（一票否决）**：
1. **项目名称**：不得直接描述技术路线/技术方法，需凝练业务痛点；30字以内，突出核心技术创新与技术进步。
2. **业务问题**：严禁描述技术问题/技术路线，必须阐述真实电网业务痛点；必须包含关键现状量化指标，无定量描述直接不通过；300字以内，明确问题对业务的负面影响、研究必要性。
3. **预期成效**：严禁堆砌过多技术细节、技术参数，避免淹没业务外特性成效；必须定量一一对应业务问题核心指标，不能偏离业务痛点；300字以内，明确成果应用场景，指标可作为验收依据。
4. **整体合规**：不得与南网科技创新战略地图方向重复；所属专业领域分类准确；自上而下项目需明确承担单位。

**深度内容评审标准**：
1. **项目名称**：精准聚焦业务瓶颈，创新技术点清晰，不宽泛笼统，体现技术迭代
2. **业务问题**：现状指标全面可量化，清晰说明问题对电网安全、运维、效益、消纳的影响，研究必要性充分
3. **预期成效**：量化指标与业务问题现状指标一一对应，明确应用场景，体现问题解决程度
4. **研究内容**：500字以内，研究点≤5个；遵循「问题分析-技术研究-试点应用」逻辑，各点相互支撑、系统性强
5. **考核指标**：500字以内，围绕核心研究内容设置；包含技术参数、应用规模、落地成效，具备先进性、可量化性、可验收性，与预期成效一一对应
6. **整体逻辑**：业务问题→研究内容→预期成效→考核指标形成完整闭环，无指标脱节、逻辑断层、空话套话

## 二、完整示例

### 样例输出

**标题**：《面向高比例新能源并网的自备电厂精准管控与协同交易关键技术研究》

**业务问题**：
目前云南电网新能源装机容量超 40GW（数据来源：《云南电网 2024 年运行报告》），新能源消纳压力突出，调峰顶峰灵活资源储备量缺口达 25%，供需平衡时段调用效率较行业标准低 18 个百分点（数据来源：行业通用指标）。作为重要可调节资源，符合调节要求的煤化工自备电厂仅 60% 纳入电网统一调度（数据来源：参考全国调节资源统筹数据，适配云南场景），其中曲靖、昭通等地参与调峰的煤化工自备电厂，15 分钟级响应指令的调度 - 交易数据传递准确率仅为 75%（数据来源：参考陕西省发改委调峰业务数据，适配云南场景），叠加响应时段划分模糊、结算流程耗时超 24 小时等问题，电厂参与调峰积极性严重不足，调节潜力未得到有效释放，亟需打通自备电厂调度协同堵点，扩充电网灵活调节资源储备。

**预计成效**：
项目完成后，试点区域内符合调节要求的高耗电工业园区自备电厂电网统一调度覆盖率提升至 95% 以上，基本实现可调节自备电厂全量纳管，消除调度纳管盲区。调峰顶峰灵活资源储备量缺口收窄至 5% 以内，供需平衡时段灵活资源调用效率达到行业标准要求，有效缓解高比例新能源并网后的消纳压力。调峰收益结算效率大幅提升，自备电厂调峰参与意愿显著增强，存量调节潜力得到充分释放，为新型电力系统灵活调节资源统筹配置提供可复制的实践路径。

**研究内容**：
针对高比例新能源并网下灵活调峰资源缺口大、高耗电工业园区自备电厂调度覆盖率低、调度 - 交易数据传递准确率不足、调峰收益结算滞后导致主体参与积极性差等问题，开展自备电厂调峰响应精准管控与协同交易关键技术研究，具体包括：
研究多类型自备电厂多时间尺度调峰响应特性，构建计及运行安全、能耗、排放约束的调峰能力精准评估模型，厘清不同工况下可调潜力边界，为调度决策提供量化支撑。
研究基于云边协同的调度 - 交易数据联动交互技术，优化 15 分钟级调峰指令传递与校验流程，破除跨系统数据交互壁垒，提升调峰响应的及时性与准确性。
研究考虑分时电价与交易价差的多主体发电权交易机制，构建兼顾新能源消纳需求与自备电厂收益的分配模型，明确调峰响应时段划分标准与快速结算规则。
研发自备电厂调峰响应管控与交易协同功能模块，选取典型高耗电工业园区开展示范应用，验证技术方案的工程可行性与实际应用效果。

**考核指标**：
形成高耗电工业园区自备电厂调峰能力评估模型 1 套，调峰潜力评估准确率≥92%，适配煤化工、钢铁、炼化等 3 类以上高耗电行业自备电厂。
建立云边协同的调度 - 交易数据联动交互技术规范 1 项，15 分钟级调峰指令数据传递准确率≥98%，指令响应时延≤1 分钟。
构建自备电厂参与调峰的协同交易与收益分配机制 1 套，调峰收益结算周期≤4 小时，自备电厂调峰参与意愿提升≥30%。
研发自备电厂调峰响应管控与交易协同系统 1 套，可接入≥20 台典型自备电厂调节资源，在 1 个及以上高耗电工业园区完成示范应用。

## 三、执行流程

### 步骤1：业务问题梳理
1. 接收用户输入的业务问题描述
2. 识别关键现状量化指标
3. 梳理核心痛点与业务影响
4. 输出规范的业务问题描述

### 步骤2：项目标题生成
1. 提取业务问题中的核心痛点与场景
2. 识别适用的技术路径与方法
3. 按照规范格式生成项目标题
4. 验证标题符合所有要求（无具体地名、字数限制等）

### 步骤3：预期成效撰写
1. 分析业务问题中的现状指标
2. 推导合理的提升空间
3. 撰写符合要求的预期成效
4. 确保不包含技术指标

### 步骤4：研究内容撰写
1. 开篇总起，点出核心痛点与研究目标
2. 分点展开，每点包含具体技术方法
3. 结尾落地，包含示范应用
4. 控制字数在450-500字之间

### 步骤5：考核指标撰写
1. 为每个研究内容点设置对应考核指标
2. 确保所有指标量化可验证
3. 包含应用场景与适配范围
4. 最后一点体现技术水平与推广价值

### 步骤6：格式审核
1. 进行形式审查（一票否决项）
2. 进行深度内容评审
3. 识别存在问题与缺陷
4. 提供优化建议
